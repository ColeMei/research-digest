## Top picks

### 1. [GLM-5.3 and the spread of advanced cyber capabilities](https://www.anthropic.com/research/glm-5-3-and-the-spread-of-advanced-cyber-capabilities)
**Andrew Fasano, Marius Fleischer, Cole McFaul, Robert Xiao, Tripp Gallagher — Anthropic Frontier Red Team · Sep 29, 2026**

The Frontier Red Team evaluates Zhipu AI's open-weight GLM-5.3 and finds exploitation ability comparable to Claude Mythos Preview: it builds end-to-end exploits in 12% of attempts on ExploitBench. The more striking result is on safeguards: attackers can bypass GLM-5.3's refusals 64–100% of the time using simple techniques such as deceptive prompts, prefilled reasoning, or abliteration. The post frames this as advanced offensive capability diffusing to models whose safeguards do not hold.

**Methodology:** Automated benchmarks (ExploitBench, an internal binary-exploitation suite) plus human-expert-led offensive tasks in sandboxes, and refusal-rate measurements on JailbreakBench, HarmBench and StrongREJECT.

**Why it matters:** A current data point on how capable open-weight exploit-writing models are, and a reminder that safeguard-based threat models for offensive-agent research are weak.

### 2. [ReproBench: Benchmarking LLM Agents on Reproducing Vulnerability From Scratch](https://arxiv.org/abs/2609.34450)
**arXiv (authors not captured) · ~Sep 28, 2026**

Existing cybersecurity benchmarks hand the agent source code, a container or a binary, skipping the environment-reconstruction step that real analysis begins with. ReproBench starts from only a CVE identifier and splits reproduction into six phases, each scored on verifiable artifacts (downloaded firmware, unpacked binaries, analysis logs, validated crash samples). On 30 real IoT-firmware vulnerabilities, 45.3% of runs fall back to "simulating" the vulnerability, and only 5.3% of CVE–model pairs achieve genuine reproduction.

**Methodology:** Phase-decomposed benchmark of 30 IoT firmware CVEs with artifact-level verification of each phase.

**Why it matters:** The 45% "simulate the bug instead" failure mode is a direct warning for any PoC-generation evaluation that only checks the final claim.

### 3. [Can Agents Trust Their Skills? Uncovering Unsafe Chains of Trust in Skill-Based LLM Agents](https://arxiv.org/abs/2609.39065)
**arXiv (authors not captured) · ~Sep 30, 2026**

Agent frameworks let users install "skills" and admit skill-provided content into the agent's context with little validation, so a malicious skill can steer the agent. The authors build TrustProbe and run it on 11 open-source agents (eight with >10k GitHub stars), reporting 104 taint-style vulnerabilities.

**Methodology:** Taint-style analysis of skill-to-context flows in open-source agent codebases.

**Why it matters:** Concrete vulnerability-finding methodology applied to the coding-agent ecosystem, which is the security of AI-empowered SE itself.

## Also notable

### [Evaluating System One Models for Agent Security Decisions: Reliability, Calibration, and Selective Automation](https://arxiv.org/abs/2609.33401)
**Yixuan Liu · arXiv · ~Sep 29, 2026 (v2 listed; v1 earlier)**
Evaluates small fast "System One" decision models against trained classifiers and LLM judges for detecting prompt injection and screening risky agent actions. Averages look good, but there are systematic failures on specific attack groups, including attacks confidently classified as safe. *Relevance:* a caution on aggregate metrics for agent guardrails.

### [SkillBloat: Token Amplification Attacks via Skill Injection in LLM Coding Agents](https://arxiv.org/abs/2608.21929)
**Yuanjin Zheng, Jingbang Chen · arXiv · v2 listed Sep 28, 2026 (original ID is 2608, so not a new submission)**
A malicious skill makes a coding agent burn 5.4x–10.1x more tokens than normal on average, an economic resource-abuse attack. *Relevance:* complements the skill-trust paper above on coding-agent attack surface.

### [Insights from the 2026 Microsoft Digital Defense Report](https://www.microsoft.com/en-us/security/blog/2026/10/01/insights-from-the-2026-microsoft-digital-defense-report/)
**Microsoft · Oct 1, 2026**
Says threat actors are adding AI to reconnaissance, social engineering, malware and exploit development, though use remains confined to specific workflow stages, and stresses identity/access control for enterprise AI agents. *Relevance:* industry framing, little technical depth.
