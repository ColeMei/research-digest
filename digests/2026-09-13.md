## Top picks

### 1. [Countering misuse of AI: September 2026 threat intelligence report](https://www.anthropic.com/threat-intelligence-report-september-2026)
**Anthropic · threat intelligence report · September 10, 2026**

Anthropic's second major case-based threat report documents malicious use of Claude from December 2025 to August 2026 across seven harm areas (cyber operations, influence operations, surveillance, scams/fraud, biological misuse, conventional weapons, model distillation). The headline shift is from interactive chat misuse toward autonomous agentic execution: LLMs embedded in multi-agent frameworks now run complex attack chains at machine speed with a human mostly just picking the target and reviewing the output. The single most striking case: Chinese-speaking operators tied to a Hunan university ran a fully autonomous, no-human-in-the-loop vulnerability-research pipeline on a preset schedule that surfaced more than a dozen candidate zero-days in major security products in one month, including working exploits against network/security-appliance product families. The report also flags a new objective for attackers — stealing AI API keys/agent-framework access as the goal, not just data — and notes that safeguards tuned to refuse a malicious request in one session hold up poorly once the same work is fragmented across many small ones.

**Methodology:** Threat-intelligence analysis of investigated/disrupted Claude usage, presented as narrative case studies across seven harm categories.

**Why it matters:** The clearest real-world evidence yet of the exact capability this digest tracks — an autonomous, scheduled, no-human-in-the-loop LLM pipeline independently finding zero-days at scale — directly at the top of the relevance bar rather than a benchmark proxy for it.

### 2. [Beyond Static Guarantees: Measuring the Static-Pass Dynamic-Fail Gap in Security-Sensitive and LLM-Generated Python Code](https://arxiv.org/abs/2609.10762)
**Jessica Pourleyli, Maitreyee Das Urmi, Glaucia Melo · arXiv cs.CR/cs.AI/cs.SE (accepted at CASCON 2026) · September 9, 2026**

Argues that a composite static-analysis gate (Bandit + Semgrep) producing zero findings is routinely treated as evidence a piece of code is secure, when static analysis structurally cannot see runtime-only exploit behavior — vulnerabilities that depend on adversarial input, execution context, or exploit chaining. The authors name this the "Static-Pass Dynamic-Fail" (SPDF) gap and build a three-stage agentic pipeline — static scanning, LLM-driven CWE reasoning, and autonomous exploit verification inside Docker containers — to measure, empirically, how often security-sensitive and LLM-generated Python code that passes static checks is still exploitable at runtime.

**Methodology:** Agentic measurement pipeline (static scan → LLM CWE reasoning → autonomous exploit verification) applied to security-sensitive Python code samples, including LLM-generated ones.

**Why it matters:** A concrete quantification of exactly the gap between "passes a security linter" and "actually secure" that matters for any secure-code-generation eval, plus a reusable agentic exploit-verification pipeline if you need one for your own benchmarking.

### 3. [Architecting the Secure AI-SOC: A Neurosymbolic Framework for Pipeline Integrity and Threat Mitigation](https://arxiv.org/abs/2609.10707)
**Anna Gazani, Spyridon Kounoupidis, Panagiotis Katsaros, Nikolaos Kekatos, Grigorios Tsoumakas, Georgios Koutidis · arXiv cs.CR · September 9, 2026**

Targets a specific attack on LLM-integrated Security Operations Centers: indirect prompt injection via log poisoning, where an adversary embeds malicious payloads inside system logs the LLM ingests for triage, hijacking its reasoning to drive multistep "promptware" kill chains against the SOC's own decision-making. The defense is a two-layer neurosymbolic pipeline — a deterministic SIEM-decoder pre-filter that structurally sanitizes volumetric padding and signature-based injections at ingestion, followed by NeMo Guardrails enforcing semantic self-checking validation on structured alerts before they ever reach the LLM.

**Methodology:** Architectural framework paper — deterministic pre-filtering + neural (LLM) guardrail validation as a defense-in-depth pipeline for LLM-driven SOC systems.

**Why it matters:** A named, concrete attack path (log poisoning → prompt injection → hijacked SOC reasoning) against the AI systems meant to defend infrastructure — directly relevant if any of your own tooling feeds untrusted log/telemetry data to an LLM.

### 4. [LLMVul: A Vulnerability-Labeled Dataset of LLM-Generated C/C++ Functions from Real Production Repositories](https://arxiv.org/abs/2609.10945)
**Mohammad Farhad, Shuvalaxmi Dass — University of Louisiana at Lafayette · arXiv cs.SE · September 10, 2026**

Fills a specific gap in secure-code-generation research: prior vulnerability datasets study either human-written code or LLM output produced under controlled/synthetic prompting, not LLM-authored code that actually made it into production. The authors mine nearly four years of real GitHub activity (Nov 2022–Sep 2026) using provenance signals (commit metadata, AI-authorship evidence) to isolate LLM-generated C/C++ functions merged into real repositories, yielding 21,430 unique functions across 226 production repos with full provenance/AI-tool metadata, and label 1,540 of them as vulnerable across 17 CWE categories using an ensemble of detectors.

**Methodology:** Large-scale GitHub provenance mining + ensemble static/pattern-based vulnerability labeling + CWE categorization, yielding a labeled dataset (not a detector).

**Why it matters:** A ground-truth dataset of real, in-the-wild LLM-authored vulnerable code (rather than lab-prompted samples) is exactly the kind of resource needed to check whether secure-code-generation findings from controlled studies actually hold up in production.

### 5. [Scanning the Harness: An Empirical Study of Supply-Chain Defects in AI Coding-Agent Configurations](https://arxiv.org/abs/2609.07360)
**Benjamin Kapner, Carmel Soceanu, Alicia Petrunin, Hofni Gartner — Red Hat / Ben-Gurion University of the Negev · arXiv cs.SE · September 7, 2026**

Points at an underexamined attack surface: the configuration layer around coding agents (Claude Code, Cursor, Copilot, Codex) — instruction files, skills, hooks, and MCP server declarations — which the authors describe as a dependency layer with no lockfile, no install-time check, and no vocabulary for what a component is allowed to do, yet which runs with the developer's own privileges. Mining 3,171 public GitHub repositories containing such configs (2,660 multi-component setups, 511 published skill collections), they catalogue recurring supply-chain defects: overly permissive tool grants, unpinned/untrusted MCP server references, leaked secrets in config, and misconfigured command auto-approval.

**Methodology:** Large-scale empirical mining and static analysis of GitHub repos containing AI coding-agent harness configuration artifacts, with a defect taxonomy.

**Why it matters:** A direct, measured look at exactly the kind of MCP/skill/hook configuration this very session runs on — worth checking your own agent setups against the defect classes it catalogues.

## Also notable

### [LLMSec-AV: A Vulnerability Taxonomy and LLM-Driven Software Weakness Discovery Framework for Autonomous Vehicles](https://arxiv.org/abs/2609.09386)
**arXiv cs.CR/cs.SE · September 8, 2026**

Builds an 18-class vulnerability taxonomy for autonomous-vehicle software from advisories and AV-security literature, then tests whether giving an LLM explicit AV-security knowledge (taxonomy context, retrieval over 374 prior disclosures, multi-step analysis) beats generic static analyzers at finding real weaknesses. Across 161 functions with 46 known weakness locations mined from upstream fixes, the best LLM condition recovered up to 76% of known weaknesses, while CodeQL, Semgrep, and Clang Static Analyzer matched none and cppcheck matched exactly one despite 1,301 alerts.

**Methodology:** Domain taxonomy construction + LLM weakness-discovery pipeline (taxonomy-conditioned, retrieval-augmented, multi-step) benchmarked against conventional static analyzers on real AV code.

**Why it matters:** A rare head-to-head where domain-adapted LLM analysis substantially beats every conventional static tool on real weaknesses rather than synthetic benchmarks — useful evidence if you need to justify LLM-based detection over rule-based tools for a safety-critical or embedded domain.

### [Agent-Integrated Software: Interaction Contracts and Continuous Assurance](https://arxiv.org/abs/2609.11381)
**Shengcheng Yu — Technical University of Munich; Chunrong Fang, Zhenyu Chen — Nanjing University · arXiv cs.SE/cs.AI · September 10, 2026**

Proposes a software-engineering pattern for applications with an agent embedded as a first-class component (not agent-as-external-coder) that can keep executing a delegated task while a user revises goals or manipulates shared state mid-task. "Interaction contracts" bind agent and non-agent components via task bindings, role-specific authority, control transitions, and outcome evidence; "continuous assurance" keeps checking agent behavior against those contracts through the running system's lifecycle rather than only at pre-deployment test time.

**Methodology:** Conceptual/architectural framework paper defining interaction contracts and a continuous-assurance process for agent-integrated software.

**Why it matters:** More methodology than empirical result, but a relevant framing if you're reasoning about run-time authority/scope boundaries for an agent embedded inside a larger system rather than one invoked as a standalone coding tool.
