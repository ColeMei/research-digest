## Top picks

### 1. [Redeploying Claude Fable 5](https://www.anthropic.com/news/redeploying-fable-5)
**Anthropic · news statement · June 30, 2026 (effective July 1)**

Anthropic's account of the 19-day US export-control suspension of Claude Fable 5/Mythos 5, triggered after Amazon researchers showed the model could be prompted to identify software vulnerabilities and, in one case, produce exploit-demonstration code. Anthropic's own follow-up testing found that less-capable models (Opus 4.8, GPT-5.5, Kimi K2.7) could reproduce the same vulnerability-identification and exploit-writing behavior, which informed the government's decision to lift the restriction with added classifiers targeting cybersecurity misuse.

**Methodology:** N/A — company policy statement, references internal red-team comparison across four frontier models.

**Why it matters:** First public blow-by-blow of a government export-control action triggered specifically by a model's autonomous vuln-ID/exploit-generation capability — directly relevant to how "AI for offensive security" capability is being measured and regulated right now.

### 2. [More details on Fable 5's cyber safeguards and our jailbreak framework](https://www.anthropic.com/news/fable-safeguards-jailbreak-framework)
**Anthropic · news statement · July 2, 2026**

Anthropic, with Amazon, Microsoft, and Google, proposes a cross-industry "Cyber Jailbreak Severity" (CJS) scale — five tiers from CJS-0 (informational) to CJS-4 (critical) — scoring jailbreaks by capability gain, breadth, weaponization ease, and discoverability. The post also announces a HackerOne bug-bounty program for researchers to report cyber-jailbreaks in Claude Fable 5, following the incident where a jailbreak got the model to flag vulnerabilities and write exploit-demonstration code.

**Methodology:** Cross-vendor severity taxonomy (CJS-0 to CJS-4) plus an external bounty program as the evaluation/reporting mechanism.

**Why it matters:** This is a benchmark/evaluation framework specifically for AI-driven security misuse severity — worth tracking as a candidate scoring rubric for your own evaluation work.

### 3. [Field reports from Patch the Planet](https://blog.trailofbits.com/2026/07/02/field-reports-from-patch-the-planet/)
**Trail of Bits (with OpenAI) · blog · July 2, 2026**

First field report from the OpenAI/Trail of Bits "Patch the Planet" initiative, describing how OpenAI's GPT-5.5-Cyber model built a bespoke zlib fuzzing campaign in a single day — work that previously took skilled human researchers weeks. The post details the human-in-the-loop workflow where Trail of Bits engineers triage and validate AI-discovered findings before submitting them upstream to open-source maintainers.

**Methodology:** LLM-driven fuzz-harness construction and campaign design, with human triage/validation before disclosure.

**Why it matters:** A concrete, disclosed example of LLM-driven vulnerability discovery outperforming manual effort on a real timeline — directly useful as a case study for vulnerability-detection tooling comparisons.

### 4. [Mastermind: Strategy-grounded Learning for Repository-Scale Vulnerability Reproduction](https://arxiv.org/abs/2607.01764)
**Mingzhe Du, Luu Anh Tuan, Tianyi Wu, Renyang Liu, Zhijiang Guo, Dong Huang, See-Kiong Ng · arXiv cs.CR/cs.SE · ~July 2026**

Proposes learning reusable "strategies" — rather than full action trajectories — for agents that inspect a repository, infer input grammar, construct a proof-of-concept exploit, and verify the crash disappears on the patched build. The dual-loop framework separates transferable strategy learning from task-specific execution experience, aiming to make PoC-generation agents generalize across repositories instead of relearning from scratch each time.

**Methodology:** Dual-loop agent framework — a strategy-learning loop distilled across tasks, and a task-specific execution loop that applies strategies to construct and verify PoCs at repository scale.

**Why it matters:** Directly on-topic for PoC generation and vulnerability reproduction — the strategy/execution separation is a reusable design pattern for any agentic exploit-generation pipeline.

### 5. [Cloak and Detonate: Scanner Evasion and Dynamic Detection of Agent Skill Malware](https://arxiv.org/abs/2607.02357)
**Zimo Ji, Congying Xu, Zongjie Li, et al. · arXiv cs.CR · ~July 2026**

Examines whether static "agent skill" scanners for LLM coding-agent marketplaces survive adaptive evasion. Third-party skills run with the agent's own privileges and can steal credentials, exfiltrate code, or install backdoors — this paper shows how such malicious skills can evade pattern-based and LLM-judge scanners, and proposes dynamic detection to catch what static analysis misses.

**Methodology:** Adversarial construction of evasive agent-skill malware samples; evaluation against static scanners (pattern + LLM-judge) and a proposed dynamic-detection approach.

**Why it matters:** Agent marketplaces (skills/plugins/MCP servers) are an emerging and under-scrutinized supply-chain attack surface — this is squarely in the "securing AI agents" lane of AI-empowered SE security.

## Also notable

### [Antaeus: Hunting Repository-Level Logic Vulnerabilities via Context-Grounded LLM Reasoning](https://arxiv.org/abs/2607.01138)
**Michele Armillotta, Nicolò Romandini, Rebecca Montanari, Lorenzo Cavallaro · arXiv cs.CR · ~July 2026**

Targets *logic* vulnerabilities (as opposed to memory-safety bugs) at repository scale in C/C++, using context-grounded LLM reasoning to infer application-specific security invariants that aren't explicit in the code — a harder detection problem than typical pattern-based bug classes.

**Methodology:** Repository-level context aggregation feeding an LLM reasoning pipeline that infers implicit security invariants and flags violations.

**Why it matters:** Logic-bug detection is one of the areas where LLM reasoning plausibly beats traditional static analysis — relevant if your vulnerability-detection work goes beyond memory safety.

An agentic vulnerability-repair pipeline augmented with external knowledge sources (rather than relying solely on the model's parametric knowledge), aimed at improving patch correctness on real-world vulnerable code.

**Why it matters:** Directly on-topic for vulnerability patching; the knowledge-augmentation angle is a useful comparison point against pure fine-tuning approaches.

### [Knowledge Over Parameters: Evolving Smart Contract Vulnerability Detection](https://arxiv.org/abs/2607.01742)
**Yuqiang Sun, Han Liu, Ying Li, Yiran Zhang, Zong Cao, Ziyun Guo, Yang Liu · arXiv cs.CR/cs.SE · ~July 2026**

Argues that external, structured knowledge outperforms raw parameter scaling for smart-contract vulnerability detection, positioning knowledge-grounding as a more efficient path than bigger models.

**Methodology:** Comparative evaluation of knowledge-augmented vs. parameter-scaled detection approaches on smart-contract vulnerability datasets.

**Why it matters:** A relevant data point for the general "knowledge-augmentation vs. scale" question in AI-driven vulnerability detection, even outside the smart-contract niche.

**Why it matters:** A practical, large-scale open-source reference for building or benchmarking your own AI red-teaming/scanning tooling.

### [An Empirical Evaluation of Prompt Injection Vulnerabilities in Large Language Models Across Multilingual and Obfuscated Attack Scenarios](https://arxiv.org/abs/2606.29602)
**Çağlar Uysal, Baturay Birinci, Süha Orhun Mutluergil, Orçun Çetin · arXiv cs.CR · June 28, 2026 (confirmed, edge of window)**

Evaluates six LLMs (DeepSeek, GPT, Gemini, Grok, Llama, Qwen) against direct and multi-stage obfuscated/multilingual adversarial prompts, showing how encoding tricks and language-switching elicit phishing emails, deceptive websites, and malware generation across models.

**Methodology:** Systematic red-teaming across six frontier/open models using multilingual and obfuscation-based prompt-injection variants.

**Why it matters:** Useful empirical baseline if you're evaluating prompt-injection robustness across model families rather than a single target model.
