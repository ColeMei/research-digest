## Top picks

### 1. [DoGNAVY-Exploit: Harnessing Parallel Open-Weight Agents for Stage-Aware Vulnerability Exploitation](https://arxiv.org/abs/2611.04196)
**Yuxuan Wang, Dadi Guo, Weijie Guo, Zikai Xu et al. · arXiv, Nov 3, 2026**
Open-weight models tend to lose track during long exploit chains. This harness breaks exploitation into milestones that can each be checked, and gives the agent only the expert knowledge relevant to the current stage. A planner proposes attack routes, executors try them in parallel, and a controller accepts progress only when there is runtime evidence for it. A shared memory keeps verified facts and records routes that failed. With GLM-5.2 it reports 97.5% Pass@1 on Cybench, 97.5% zero-day / 100% one-day on CVE-Bench, and 79 ExploitGym tasks solved against 39 for a Claude Code baseline.
**Methodology:** A hierarchical planner/executor/controller multi-agent harness with structured memory, evaluated on Cybench, CVE-Bench and ExploitGym, with ablations.
**Why it matters:** It is a strong open-weight baseline. The evidence-gated, stage-aware design is something you can reuse directly in offensive-agent harnesses.

### 2. [A thousand fewer paths to root](https://openai.com/index/a-thousand-fewer-paths-to-root)
**OpenAI · Nov 4, 2026**
OpenAI describes an autonomous pipeline that found, reproduced, exploited and patched 948 distinct Linux kernel local privilege-escalation bugs, which it counts by distinct patch. Secondary coverage gives the funnel: about 2,308 candidates, 1,724 dynamically reproduced, 1,169 working LPE exploits and 291 info-leak PoCs, at roughly $1.2M in API credits (about $1,280 per exploit). Disclosure is staged through the Patch the Planet partners. The article page was blocked, so these numbers come from the feed summary and search coverage, not the post itself.
**Methodology:** An end-to-end agent pipeline (hunt → dynamic repro → exploit → variant dedup → patch) run at kernel scale with an unreleased cyber model.
**Why it matters:** It is the largest public data point so far on cost per exploit and on the hunt-to-patch funnel, which is useful framing for any paper on automated exploitation.

### 3. [A.S.E 2.0: Understanding How Repository Context Impacts the Security of LLM-Generated Code](https://arxiv.org/abs/2611.06294)
**Jiongchi Yu, Keke Lian, Junqing Wang, Zhikang Fan et al. · arXiv, Nov 4, 2026**
CASE-Bench has 145 repository-level tasks drawn from real CVEs in 51 projects. Each task has a Docker environment, functional tests and a PoC exploit validated in both directions. Context aimed at functionality raises functional pass by up to 8.2pp but secure pass by only 3.7pp. Hiding one safeguard lowers secure pass by 8.1pp, and inserting one insecure example raises exploitable-but-correct code by 6.3pp. Agents see the relevant safeguard in only 27–36% of trajectories.
**Methodology:** A benchmark comparing 13 context-construction methods and six controls across six LLMs, with single-element context edits and agent trajectory analysis.
**Why it matters:** It places the security of AI-generated code in context retrieval rather than in the model alone, which points to a concrete research lever.

### 4. [A Gingerbread House for LLM Agents: Source-Planned Honeypots That Lure Autonomous Attackers into an Isolated Shadow](https://arxiv.org/abs/2611.07611)
**Seungdeok Roh, Seokjun Ryu, Sohee Park, Daeseon Choi · arXiv, Nov 5, 2026**
An LLM defender reads an application's source and plans a honeypot. Once a client is confirmed as an attacker, all of its later requests go to an isolated shadow copy. On the 40 critical CVE-Bench tasks, real compromise fell from 26/40 to 5/40 against Claude Opus 4.8 and from 20/40 to 0/40 against ARTEX. ARTEX reported a planted fake secret as genuine in 30 of 120 runs. The authors are clear that the exploit still works, but only against the shadow.
**Methodology:** Three defence arms (none, static plan, static plan plus runtime LLM responder) tested against LLM attacker agents and scored by CVE-Bench's grader.
**Why it matters:** It is a ready-made defensive counterpart for offensive-agent evaluations. It also matches Microsoft's "fake wins" advice in this week's ARTEX update.

### 5. [Analysis of Local Open-Weight LLM Agents on Vulnerability-Reproduction Tasks](https://arxiv.org/abs/2611.06257)
**Jorge García-Carrasco, Javier Sanchis, Álvaro Navarro, Alejandro Maté et al. · arXiv, Nov 4, 2026**
The paper asks whether models that fit on one consumer GPU can turn a vulnerability description into a crashing input. It tests 12 configurations (three model generations, two architectures, three quantization levels) on 10 CyberGym tasks with three runs each. A 4B model solves most of the easier tasks, but the hardest ones need the 27B model. Quantization changed speed but never which tasks were solved. Agents usually identify the right function and hypothesis; where they fail is in turning that hypothesis into a working input.
**Methodology:** A controlled single-harness evaluation on a CyberGym subset, with trajectory analysis and released artefacts.
**Why it matters:** It pins down the bottleneck (input construction, not localization), which tells you where tooling or training would help most.

## Also notable

### [GPT-6 Cyber: Advancing the frontier of aligned cybersecurity agents](https://openai.com/index/introducing-gpt-6-cyber)
**OpenAI · Nov 5, 2026**
A new cybersecurity model trained to find and fix exploitable bugs while staying inside the scope a researcher authorizes. Reported figures: 48.5% on ExploitGym (GPT-5.6 Cyber: 32.1%), and 99.93–100% out-of-scope avoidance on a honeypot test where attacking supporting services counts as a violation. OpenAI rates it "Critical" under its Preparedness Framework, and access is limited to Daybreak Red customers. The numbers come from the feed and search coverage because the page was blocked, and there is no third-party evaluation yet.
**Methodology:** Scope-alignment training, evaluated on exploitation benchmarks plus a scope-violation honeypot.
**Why it matters:** "Scope adherence" is now reported as a metric next to capability, and offensive-agent benchmarks may need to report it too.

### [Keeping Fuzzers on Duty: Repairing Fuzzing Build Breakages in Continuous Open-Source Fuzzing](https://arxiv.org/abs/2611.06358)
**Zhuang Zhao, Jiongchi Yu, Yao Zhang, Dongge Liu et al. · arXiv, Nov 4, 2026**
About 20% of OSS-Fuzz projects are in a broken-build state, so their fuzzers are not testing anything. FuzzMedic diagnoses these breakages using evidence from both the project and the fuzzing infrastructure, and explores repairs over a state graph with rollback. A patch is accepted only if the fuzz targets actually run again. It fixes 48.44% of 128 reproducible failures, and 29 of its patches have been merged upstream.
**Methodology:** A long-horizon LLM repair agent with graph search over workspace states, deployed in practice.
**Why it matters:** It is a clean example of a repair agent with a strong, execution-based validation oracle.

### [SBVUL: Statement-Based Vulnerability Detection](https://arxiv.org/abs/2611.06135)
**Martin Pinzger, Katharina Stengg, Christian Macho, Stefan Schöberl et al. · arXiv, Nov 4, 2026**
A two-agent pipeline finds exploitable statements in C/C++ code: one agent proposes candidate statements and a second confirms them through control- and data-flow analysis. On 200 hand-annotated PrimeVul pairs, Phase 1 finds the ground-truth statements in 56–77% of vulnerable functions. The verifier still "confirms" bugs in 23–61% of patched functions. Best statement-level precision is 0.315 at 0.605 recall.
**Methodology:** A localize-then-verify multi-agent pipeline with a new statement-level ground truth and an LLM judge.
**Why it matters:** The false-confirmation rate on patched code is a warning sign for verifier agents in any detection pipeline.

### [Backporting security fixes at scale with Codex](https://blog.trailofbits.com/2026/11/02/backporting-security-fixes-at-scale-with-codex/)
**Artem Dinaburg, Trail of Bits · Nov 2, 2026**
Codex agents find CVE fixes that are missing from stable branches, adapt the patches, collect validation evidence, run tests and prepare submission packets. Engineers review everything before it goes to maintainers. As of Oct 29 the pipeline had landed 149 CVE fixes in stable Linux kernel trees, at about 30 minutes of human time per simple backport and about 3 hours per complex one. The post also measures the backlog, for example 2,006 unfixed CVEs in kernel 5.10.y.
**Methodology:** An agent pipeline that starts with clean-apply fixes and moves to harder adaptations, with a human review gate.
**Why it matters:** Patch backporting is a neglected, well-defined repair task, and this post supplies real-world numbers for it.

### [Making HTTP header injection critical with one prompt](https://portswigger.net/research/making-http-header-injection-critical-with-one-prompt)
**Tom Stacey, PortSwigger Research · Nov 4, 2026**
PortSwigger turned its CRLF-desync research into a Burp agent skill that takes a header-injection finding and escalates it on its own. The four phases are: locate the upstream injection point, validate request splitting, find redirect gadgets, and prove impact with a Collaborator redirect. They deliberately left out response-queue poisoning as too dangerous to real users. Each phase can bail out cleanly and hand control back to the tester.
**Methodology:** Expert methodology encoded as a phased agent skill, with safe exploit choices and bail points.
**Why it matters:** It is a practitioner template for adding safety constraints to pentest agents, at the level of individual steps.

### [VeriHarm-Bench: Measuring Harmful Success in LLM Coding Agents Verifiably](https://arxiv.org/abs/2611.03575)
**Wei-Lin Chen, Zhepei Wei, Xinyu Zhu, Yu-Min Tseng et al. · arXiv, Nov 2, 2026**
The paper defines "harmful success": a coding agent finishes the task but causes side effects, such as deleting files or weakening permissions. VeriHarm perturbs coding tasks so they invite such harm and generates executable harm tests alongside the correctness tests. Frontier agents average 95% task accuracy but only about 37% safe success.
**Methodology:** Automated benchmark construction with programmatic harm oracles.
**Why it matters:** It shows that task-success metrics alone overstate how safe coding agents are.

### [Beyond Prompt Injection: The Tool Update Gap in LLM Agent Security](https://arxiv.org/abs/2611.01976)
**Shiyu Kan, Yue Qi, Yufei Han, Xinjian Luo et al. · arXiv, Nov 1, 2026**
Agent frameworks keep trusting a tool after its code changes. ETUDE hides malicious behaviour in updates to tools that were originally benign, while the tools keep working normally. Because the payload runs outside the LLM's context, defences that inspect only what the model sees miss it. It reaches 97.6% attack success across seven frameworks, including Claude Code, Codex CLI and Gemini CLI.
**Methodology:** An attack design evaluated over three workloads, seven agent frameworks and existing defences.
**Why it matters:** It extends the coding-agent supply-chain threat seen in recent weeks (LiteLLM, the fake Cursor extension) to tool updates.

### [Does Frontier AI Strengthen Cyber Defense? Evidence from Project Glasswing](https://arxiv.org/abs/2611.06629)
**Thomas Mosk · arXiv, Nov 4, 2026**
The paper treats early access to Claude Mythos Preview under Project Glasswing as a natural experiment. Firms with access more than doubled their vulnerability disclosures and disclosed about 150% more high-impact bugs than comparison firms without access. External bug-bounty researchers shifted their effort to other firms. The share of disclosed vulnerabilities exploited within a month fell by about two-thirds. The author also notes the access asymmetry this creates.
**Methodology:** A difference-in-differences style analysis of all publicly disclosed vulnerabilities.
**Why it matters:** It is rare causal-style evidence on whether AI vulnerability finding helps defenders in practice. The single author and the choice of comparison firms (Chinese and Russian) are worth checking.
