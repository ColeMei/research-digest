## Top picks

### 1. [CrossPloit: A Benchmark for Cross-Version PoC Migration in Python Web Applications](https://arxiv.org/abs/2611.16588)
**Hung Nguyen-Huu, Nguyen Anh Tuan, Ting Zhang, Yue Liu et al. · arXiv, Nov 12, 2026**
Vulnerability databases often give incomplete affected-version ranges, so some vulnerable releases look safe. Proving they are vulnerable means adapting a working PoC so it triggers the same bug on an earlier, unlisted version. CrossPloit has 127 such migration tasks across 45 CVEs, and building it uncovered 149 vulnerable versions missing from four databases. Across 18 agent configurations (9 models × 2 harnesses) the best solves 58.3%, against 8.7% for a trace-guided baseline. No configuration gets above 37.9% when the attack vector changes, and withholding the reference PoC drops one configuration from 50.4% to 15.0%.
**Methodology:** An execution-based benchmark with version-pinned containers, a reference PoC, a vulnerability-specific oracle and two validators per task.
**Why it matters:** It is an offensive-agent benchmark checked by execution and tied to real under-reported exposure, so you can use it directly as a testbed for PoC generation.

### 2. [Lessons from 59 Linux Kernel Bug Reports](https://www.microsoft.com/en-us/security/blog/2026/11/11/lessons-from-59-linux-kernel-bug-reports/)
**Microsoft FORGE Lab and Cen Zhang · Nov 11, 2026**
FORGE ran its AI scanner (MDASH, mostly Sonnet 4.6 plus GPT-5.4/5.5) over kernel networking, filesystem and LSM code. The 26,502 raw findings were screened down to 11,769 candidates. QEMU PoC agents then produced 621 PoC-backed cases, which became 59 upstream reports, 33 CVEs (24 rated High or above), 38 merged fixes and 8 working local-root exploits. Of the 621 PoC cases, 42.8% duplicated another case's root cause, 26.2% had too little impact and 21.4% were already known. Upstreaming took more than four person-months.
**Methodology:** A multi-model funnel (scan → screening agents → PoC reproduction in QEMU → expert root-causing, dedup and upstreaming), with counts at each stage.
**Why it matters:** It is an independent industrial funnel to compare with OpenAI's 948-exploit post from last week. It has real attrition and human-effort numbers, and it shows the bottleneck is now validation and dedup, not discovery.

### 3. [BypassGym: A Benchmark for Evaluating AI Agents' Endpoint Defense Evasion Capabilities](https://arxiv.org/abs/2611.13684)
**Weifeng Yuan, Zifan Chen, Yucheng Zhang, Feng Dong et al. · arXiv, Nov 10, 2026**
An agent is given C2 shellcode and must write and compile a loader that runs it without being blocked by real EDR products. The EDRs run on Windows VMs and send structured detection feedback back to the agent. The authors test 5 lightweight model backends against 6 EDRs and 3 payloads, with and without an evasion-knowledge skill. Even cheap models succeed: DeepSeek-V4.1 Flash wins 17 of 18 runs, and the hardest EDR (Bitdefender) still lets 5 of 15 runs through.
**Methodology:** A live-environment agent benchmark with a feedback loop from real EDR products, plus an ablation with and without domain knowledge.
**Why it matters:** It covers defense evasion, a kill-chain stage that pentest and CTF benchmarks skip, and the high success of cheap models is a capability datapoint worth citing.

### 4. [Look Here, Then Decide: Small Decision Models in a Harness Find Memory-Safety Vulnerabilities at Scale on Commodity GPUs](https://arxiv.org/abs/2611.16565)
**Tim De Wachter, Kyryl Volkov, Myrto Eleftheria Gkogkou, Mathieu Huysman · arXiv, Nov 12, 2026**
Deterministic miners and localizers select candidate C/C++ functions, and a 4B open-weight model ranks them; no frontier model is used. On its own the model is weak: AUC is 0.73 for vulnerable vs. benign and 0.56 for a vulnerable function vs. its own patch. As a ranker it helps: on 75 CVEs it puts the fixed function in the top 25 1.4× as often as random order (21% of cases). The live campaign covered more than 4,000 projects at about 1,000 repos per hour and confirmed 187 memory-safety findings (12 critical), now under coordinated disclosure.
**Methodology:** Deterministic localization plus small-model prioritization and verification, evaluated on held-out CVEs and a live campaign.
**Why it matters:** It is an honest account at real scale: the model is useful for prioritization, not detection, and the harness does most of the work.

### 5. [Coding Agents Propagate Vulnerabilities in Code Bases](https://arxiv.org/abs/2611.11455)
**Chenhao Sun, Niels Mündler-Sasahara, Mark Vero, Martin Vechev · arXiv, Nov 8, 2026**
The paper tests whether vulnerabilities already in a repository lead coding agents to write similar ones, using 96 backend tasks and 20 C/C++ memory-safety task pairs. Insecure neighbouring code lowers correct-and-secure backend implementations by 3.4% on average, and on C/C++ the gap between secure and insecure contexts reaches 35.4%. Security prompting reduces the effect but does not remove it. Agents said they were copying existing code in 76.5% of cases, and recognized the vulnerability they had introduced in 69.9%.
**Methodology:** Controlled paired experiments varying how secure the surrounding code is, with prompting ablations and analysis of the agents' self-explanations.
**Why it matters:** Together with last week's A.S.E 2.0, it shows that repository context drives the security of AI-generated code, and the effect compounds as agents write more of the code base.

## Also notable

### [Introducing Claude Fable 5.2 and Claude Mythos 5.2](https://www.anthropic.com/claude-fable-and-mythos-5-2)
**Anthropic · Nov 9, 2026**
Fable 5.2 is generally available, with classifiers that block pentesting, exploit-generation and binary-vulnerability work. Mythos 5.2 has no such safeguards and goes only to vetted organizations through the Cyber Verification Program. On CyScenarioBench, Anthropic reports Mythos 5.2 at 76.3%, Opus 5.5 at 67.6% and GPT-6 Cyber at 61%. On internal CVE rediscovery (1,829 CVEs) it reports 89.6%. Unauthorized use of credentials or files outside the sandbox fell to 3.1% of scenarios, from 21% for Mythos 5.1.
**Methodology:** A vendor launch post that relies on internal benchmarks.
**Why it matters:** It is the first head-to-head figure against GPT-6 Cyber and adds sandbox escape as a reported metric. The evals are internal, so treat the numbers as claims.

### [Say Shibboleth: Fingerprinting the LLMs and Harnesses Behind Agentic Attacks](https://arxiv.org/abs/2611.12386)
**Dario Pasquini, Reworr, Giuseppe Ateniese, Manish Bhatt et al. · arXiv, Nov 9, 2026**
"Shibboleth traps" are honeypot services that make an attacking agent reveal information before it gets the resource it wants, without needing a successful prompt injection. Behavioural probes reveal how the harness masks secrets, enforces time limits and schedules tool calls. Combining these signals identifies the model among 15 candidates with 90% top-1 accuracy and the harness among four with 92% accuracy. Agents told to hide their identity still leak behavioural evidence.
**Methodology:** Honeypot-based fingerprinting with declarative and behavioural classifiers, evaluated on held-out harnesses and task families.
**Why it matters:** Offensive-agent evaluations could report how attributable an agent is, not only how often it succeeds.

### [Preserve the Vulnerability, Break the Alert: Testing the Robustness of CodeQL Taint Tracking with Natural Rewrites](https://arxiv.org/abs/2611.17123)
**Zhezhen Cao, Weiyuan Ding, Bowen Xu · arXiv, Nov 12, 2026**
An LLM that sees only the CodeQL alert rewrites one function as a plausible maintenance change that keeps the vulnerability but silences the alert. On 172 real npm vulnerable flows, three tries per flow silence 26.2% of alerts at about $0.51 each, while plain refactoring silences none. Every silencing rewrite exploits one of seven gaps in how CodeQL models libraries, and 74% also evade an independently built taint analyser.
**Methodology:** LLM-generated rewrites that keep the vulnerability, checked by manual audit and controlled experiments.
**Why it matters:** A disappearing SAST alert is weak evidence of a fix, which matters if you use static analysis as an oracle or reward in LLM repair.

### [Beyond the Diff – VulSpot: A Vulnerability Dataset Where No Vulnerability Goes Unlocalized](https://arxiv.org/abs/2611.15737)
**Dyna Soumhane Ouchebara, Stéphane Dupont · arXiv, Nov 11, 2026**
VulSpot is a living dataset of more than 500k functions in 21 languages, drawn from 24k CVEs. It links code a patch adds, such as a new NULL check, back to the existing statement that code protects. This localizes 99.3% of the functions that diff-based datasets leave without a location. It also provides label-reliability scores, leak-free splits, hierarchical CWE labels and a monthly refresh.
**Methodology:** A dataset built from CVE fix commits, linking add-only patches to what they protect, with label-reliability estimates.
**Why it matters:** It targets the label-noise, leakage and localization problems raised by last week's PrimeVul reassessment, and the monthly refresh limits contamination.

### [Blind trust: stealing credentials through CSP](https://portswigger.net/research/blind-trust-stealing-credentials-through-csp)
**Gareth Heyes, PortSwigger Research · Nov 11, 2026**
A CSP that blocks all scripts can still leak credentials, because `form-action` does not fall back to `default-src`. An injected form posts back to the same page, and a second-stage payload (meta referrer plus meta refresh) sends the credentials out in the Referer header, with no script running. PortSwigger shipped the technique as a skill for its agentic Burp tool. The skill resolves CSP fallback chains, checks allowed hosts against more than 350 known bypass gadgets and builds a Collaborator PoC.
**Methodology:** A new exploitation primitive written up as a deterministic pentest-agent skill and demonstrated on a lab page.
**Why it matters:** It is PortSwigger's second example in two weeks of turning expert research into a pentest-agent skill with a defined scope; there are no evaluation numbers.

### [FORGE Lab uses agentic tools to identify memory safety issues in Rust](https://www.microsoft.com/en-us/security/blog/2026/11/09/forge-lab-uses-agentic-tools-to-identify-memory-safety-issues-in-rust/)
**Yechan Bae and Microsoft FORGE Lab · Nov 9, 2026**
Agent-assisted auditing found soundness bugs in Rust's core and std libraries where safe code can trigger undefined behavior. The bugs fall into three patterns of misplaced trust: panic safety (e.g. MapWindows::clone), trusting user-supplied trait implementations (including an incomplete fix to the 2020 `join` CVE) and trusting the system (process::exit and the signal stack, CommandExt::exec racing on environ). The authors argue that agents beat classic analyzers such as Rudra on bugs at the system boundary.
**Methodology:** Agent-assisted auditing with hand-written PoCs and fixes coordinated with maintainers; no totals or effort figures are given.
**Why it matters:** The taxonomy and the real issue IDs could seed a benchmark for detecting Rust soundness bugs, which is an underexplored target.

### [Trained to betray: How post-training supply chain attacks hijack coding agents](https://www.microsoft.com/en-us/security/blog/2026/11/12/trained-to-betray-how-post-training-supply-chain-attacks-hijack-coding-agents/)
**Microsoft Defender Research and AI Red Team · Nov 12, 2026**
Poisoning about 1% of a fine-tuning set (90 of about 9,000 conversations) made gpt-4.1-mini run a fetch-and-execute command in about 78% of trials on harnesses seen in training, but only 0–11% on unseen ones. Backdoored Qwen3.5-4B and 9B checkpoints trained with SFT plus RL fired in 84–95% of trials on unseen repositories. The backdoors carried over to Claude Code (97/91% for 4B/9B), Pi and Codex CLI. A short GRPO phase restored benign coding performance while keeping the backdoor.
**Methodology:** Controlled poisoning experiments with 500 trials per harness, held-out harnesses and repositories, and ablations.
**Why it matters:** It is the clearest empirical threat model so far for backdoored coding agents, and standard capability evals would not catch it.

### [What a CAGE 4 Score Measures: An Audit of a Learned Cyber-Defense Benchmark, Its Reference Defenders, and the Tables Built on Them](https://arxiv.org/abs/2611.14068)
**James Rice, Ji Hwan Park, Andres Kwasinski · arXiv, Nov 10, 2026**
Reproducing the reference defenders for CAGE Challenge 4 showed that the simulator silently drops actions sent to busy agents while still charging for them. Removing an undocumented busy-flag check costs the reference defenders 99.58 and 145.98 points per episode. 88.9% of per-episode variance comes from unseeded policy sampling, and none of five published comparison tables can be compared like for like.
**Methodology:** A reproduction audit in a pinned container, with ablations and variance decomposition; the authors release patches and a disclosure checklist.
**Why it matters:** It is a template for auditing any multi-agent security benchmark you build on.
